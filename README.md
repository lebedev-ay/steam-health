# steam-health

Аналитика здоровья игр в Steam: ищет день, когда патч или новость заметно сдвинули долю позитивных отзывов. Собирает отзывы и новости через Steam API, раскладывает их в хранилище и рисует кривую настроения с отметками событий и найденными точками перелома. Источников событий три: новости самой игры, внешняя игровая пресса (часть анонсов проходит мимо Steam) и события платформы целиком - распродажи, Steam Awards, Next Fest.

Живой стенд: [steam-health.ru](https://steam-health.ru)

![Дашборд steam-health: кривая доли позитивных отзывов Diablo IV за год, отметки событий и найденные точки перелома](docs/img/dashboard.png)

## Как устроено

`raw` хранит ответы Steam API как пришли, только дописывается. `core` - звезда: `dim_game` со SCD2-историей версий игры, факты по отзывам и патчам, справочники и мосты. `marts` - витрины поверх core, из них читает дашборд.

Наполняют raw и core скрипты из `collector/`, схему core держат миграции в `db/migration/`, витрины строит `dbt/`. Витрина - это всегда select над тем, что уже в базе, поэтому сразу после миграций схема marts пуста, и наполняет её `dbt run`.

Запускается всё это двумя способами: кнопкой на дашборде для одной игры и ежедневным прогоном Airflow по всем. Код у обоих путей общий.

Таблицы, диаграммы и то, что реально заполняется, - в [docs/model.md](docs/model.md). Почему сделано именно так - в [журнале решений](docs/decisions.md), там же отвергнутые варианты.

## Что на дашборде

**Главная** - все игры карточками или списком: доля позитива за последние 30 дней, изменение к прошлым 30, словесная оценка по правилам Steam и полгода по неделям. Поиск по названию, жанру и разработчику, фильтры по жанру, тренду и наличию разбора моделью, сортировки; всё это хранится в адресе. Быстрый переход к игре - клавиша `/` или Ctrl+K.

**Страница игры** открывается с главного: сводка месяца от модели, кольцо «здоровья» за 30 дней и ключевые числа. Дальше - вкладки для тех, кто хочет покопаться:

- **Обзор** - доля позитивных отзывов по дням с нормой игры, под ней объём, ромбы - переломы. Над графиком - дорожка событий: засечки новостей игры (чем выше, тем важнее) и событий Steam, самые важные подписаны. Сколько событий показать, решает ширина экрана и приближение: на общем виде только главное, при приближении проявляются мелкие. Рядом последние переломы, несколько фактов коротко и самые полезные отзывы месяца.
- **Переломы** - карточка на каждый: сдвиг, доля позитива и объём за неделю до и после, ближайшее событие и разбор моделью, если игра размечается; без разбора - слова, которые чаще писали на той неделе. Из карточки открываются отзывы этой недели.
- **Темы** - слова отзывов для любой игры, без модели: какие слова стали чаще у довольных и недовольных за 30 или 90 дней и о чём пишут вообще; щелчок по слову открывает отзывы с ним. У размечаемых игр ниже - темы по справочнику, критика по месяцам и архив сводок; щелчок по теме - её история и цитаты.
- **Аудитория** - доля позитива по наигранным часам, языку, способу получения игры, раннему доступу и ответу разработчика.
- **Обновления** - реакция на каждую новость игры: позитив и объём за неделю до и после, с сортировкой.
- **Отзывы** - сами отзывы за период с фильтром по оценке и языку; у размеченных - теги тем.

Игра и вкладка хранятся в адресе (`/?app=892970&tab=topics`), ссылкой можно поделиться.

## Стек

Python, PostgreSQL 16, dbt, Airflow 3, Celery + Redis, Docker, Flask + Plotly. Metabase и Power BI пробовались и не подошли - причины в записи 012 журнала.

## Запуск

```bash
cp .env.example .env   # заполнить пароль
docker compose up -d --build
```

Поднимутся postgres и redis, применятся миграции, соберутся витрины, запустится дашборд на gunicorn - http://localhost:5000. База при этом пустая: данные собираются формой в шапке дашборда либо коллекторами вручную.

Airflow под профилем и обычным `up` не поднимается:

```bash
docker compose --profile airflow up -d   # http://localhost:8080
```

Логин `admin`, пароль из `AIRFLOW_ADMIN_PASSWORD`. Порт открыт только на петлевом интерфейсе, снаружи недоступен; на сервере заходить через туннель `ssh -L 8080:127.0.0.1:8080`.

Для разработки дашборд удобнее держать снаружи docker, чтобы он перезапускался сам при правке кода. Порядок команд - в [docs/model.md](docs/model.md).

## Сбор данных

Добавлять и обновлять игры могут только вошедшие: кнопка «+ Игра» в шапке ставит задачу в очередь и опрашивает статус, не блокируя графики. Регистрации нет - учётки выдаёт владелец:

```bash
docker compose exec web python users.py add anna      # пароль спросит дважды, в историю shell он не попадёт
docker compose exec web python users.py list
docker compose exec web python users.py disable anna  # вход и открытые сессии перестают работать сразу
```

Для входа нужен `SECRET_KEY` в `.env` - им подписывается сессия. Пароли хранятся хэшами werkzeug, кука сессии - HttpOnly, SameSite=Lax и Secure, попыток входа не больше 10 за 15 минут с одного адреса. Задача проверяет игру в Steam, качает карточку, новости и отзывы, грузит их в core и пересобирает витрины.

Глубина задаётся днями: `COLLECT_REVIEW_DAYS` по умолчанию 365, `COLLECT_REVIEW_PAGES` в 200 страниц - страховка от бесконечного обхода. У популярной игры предел страниц срабатывает раньше даты: полный сбор Rust принёс 55 дней истории за 9 минут, а у тихой Medieval Dynasty 58 страниц покрыли 366 дней за 3.5 минуты. За большей глубиной идти коллектором руками (запись 036).

Сборы по кнопке выполняются по одному, замок держится в Redis. Запись в ядро и пересборка витрин защищены отдельным замком в PostgreSQL - он общий для кнопки и ночного прогона (запись 041). Ручная цепочка коллекторов и загрузчиков описана в [docs/model.md](docs/model.md).

## Разметка новостей

Масштаб события по заголовку и длине патчноута не определить: релиз 1.0 бывает коротким постом, а сотня мелких исправлений - длинным. Поэтому новости игр размечает модель (`llm/news.py`): уровень (веха, крупное, обычное, фон), вид (релиз, дополнение, сезон, баланс, хотфикс…), анонс это или уже случилось, и короткое русское название для подписи на графике. Модель видит заголовок и начало текста; размечаются собственные новости игры, пресса - нет. Новостей в сотни раз меньше, чем отзывов, поэтому размечаются все игры.

С разметкой дорожка событий показывает вехи на любом масштабе, крупное - до года, остальное - по бюджету ширины. Без неё важность считается по-старому: тип из заголовка, вес, отклик в отзывах.

Порядок первого запуска:

```bash
docker compose exec worker python -m llm.news --export-sample 60 > llm/gold/news_gold.json   # заполнить tier, kind, future руками
docker compose exec worker python -m llm.news --ids-file llm/gold/news_gold.json            # разметить эталон
docker compose exec worker python -m llm.news --eval llm/gold/news_gold.json                # согласие по уровню, виду, анонсу, расхождения по вехам
docker compose exec worker python -m llm.news --all --dry-run                                # сколько новостей и оценка цены
docker compose exec worker python -m llm.news --all
```

Затем в `dbt/dbt_project.yml` задать `llm_news_prompt_hash` - начало хэша промпта из вывода команды - и пересобрать витрины. Пока хэш пуст, `marts.news_label_current` пустая, и дашборд работает без разметки.



DAG `steam_daily` в 03:00 UTC обходит все игры, которые уже есть в базе: собирает отзывы и новости параллельными ветками, догружает новое в core и пересобирает витрины с проверкой тестами. Обычный прогон занимает полторы минуты - загрузка инкрементальная, по метке порции сырья (запись 040).

У сетевых задач ретраи, у остальных нет: если упала загрузка, повтор через пять минут не поможет. Если сбор не удался, витрины не пересобираются вовсе - дашборд показывает вчерашние данные, но целые.

Схема запуска - [docs/er/orchestration.drawio](docs/er/orchestration.drawio). Почему Airflow, а не cron, и какой ценой он живёт на сервере с 1,9 ГБ памяти - записи 038, 039 и 042.

## Как читать переломы

Детектор не доказывает причинно-следственную связь. Он ранжирует дни по силе сдвига доли позитива и показывает верхушку: для каждого дня берётся разница между средним за следующие семь дней и средним за предыдущие семь, а порогом служит среднее плюс несколько сигм от разброса самого ряда.

![Декабрьский обвал Diablo IV: доля позитива падает на 57.8 п.п. после публикации о дате дополнения и восстанавливается с началом сезона](docs/img/changepoint.png)

Порог относительный, поэтому число найденных точек зависит в первую очередь от настройки чувствительности, а не от того, насколько бурной была жизнь игры. У ровной игры на высокой чувствительности переломы найдутся тоже. События рядом с точкой (±3 дня) подставляются как возможное объяснение, и совпадение по времени - это всё, что о них известно.

Края ряда не оцениваются: сдвиг не считается, пока в окне «до» или «после» меньше трёх дней.

## Что где лежит

- `collector/` - сбор данных и загрузка в хранилище
- `db/migration/` - миграции схемы core
- `dbt/` - модели витрин marts
- `web/` - дашборд на Flask + Plotly: один запрос `/api/game/<app_id>` на страницу игры
- `airflow/` - образ, DAG и логи оркестратора
- `llm/` - LLM-разметка отзывов по темам, выводы по переломам и сводки месяца
- `api/` - черновые запросы к Steam API в формате `.http`; не часть пайплайна
- [docs/model.md](docs/model.md) - модель данных, схема core, витрины, запуск
- [docs/decisions.md](docs/decisions.md) - журнал решений
- [docs/TODO.md](docs/TODO.md) - что не сделано и что отложено осознанно
